# GoodKota Evolution Roadmap

## V1.0 — Operating flow
Validate the three-sided product:
- customer ordering
- merchant fulfilment
- marketplace administration

## V1.1 — Identity and persistent backend
Likely areas:
- real customer/merchant/admin identities
- persistent database
- merchant ownership and permissions
- audit fields
- server timestamps

## V1.2 — Merchant onboarding
- merchant application
- verification state
- operating profile
- business documents where required
- merchant-specific settings

## V1.3 — Payments
- payment-provider abstraction
- payment intent/order relationship
- payment status independent from order status
- refunds and failed-payment handling

## V1.4 — Delivery integration
- delivery quote abstraction
- delivery provider adapter
- dispatch status
- delivery event history

## Later
- customer accounts and favourites
- ratings/reviews
- merchant analytics
- promotions/referrals
- notifications
- scheduled menus
- richer catalogue options/modifiers
- commercial subscription billing

The roadmap is intentionally incremental. GoodKota should prove merchant and customer behaviour before adding infrastructure complexity.
